계획 (Plan)

ytdown

유튜브 영상을 MP3(오디오) 또는 MP4(영상)로 다운로드하는 작은 앱입니다. 링크를 붙여넣고, 형식을 고르고, 버튼을 누르면 파일을 받습니다. UI는 React + TypeScript(Vite 빌드), 백엔드는 작은 TypeScript Node 서버입니다. 실제 다운로드는 교체 가능한 download.sh에 격리된 내 yt-dlp 명령이 담당합니다. 두 단계로 만듭니다: (A) 로컬에서 만들고 테스트, 그다음 (B) IONOS VPS에 HTTPS + 비밀번호 뒤에서 배포.

개인 사용 전용 — 공개되면 더 중요합니다. 본인이 소유했거나, 퍼블릭 도메인/CC, 혹은 저장할 권리가 있는 콘텐츠만 다운로드하세요. 인터넷에 열어둔 유튜브 다운로더는 반드시 발견되어 악용됩니다. 그래서 Phase B는 인증 뒤에 둡니다 — 절대 열어두지 마세요.

1인용 도구 — 나만 씁니다. 비밀번호 하나(HTTP Basic Auth)가 전체 로그인: 가입·계정·DB 없음. 앱 UI는 영어입니다. (이 계획 문서의 한국어 버전이 PLAN.html, 영어 원본이 PLAN.md. 구현 설명은 HOW-IT-WORKS.md 참고.)

0. 두 단계

단계위치목표
A내 Mac (127.0.0.1)다운로드 흐름 완성: URL → MP3/MP4 파일
BIONOS VPS (<VPS_IP>, Ubuntu 24.04)https://<도메인>에서 비밀번호로 보호하여 제공 (CloudPanel)

A를 먼저. 같은 앱을 로컬에 바인딩할 뿐입니다. B는 대부분 운영 작업(빌드, 리버스 프록시, TLS, 인증, 프로세스 매니저).

1. 목표 & 범위

목표: 한 화면 → 유튜브 URL 붙여넣기 → MP3/MP4 선택 → 브라우저에서 파일 받기.

범위 (v1):

  • 한 번에 영상 1개 (동시에 1개 작업만 — VPS RAM 2GB라 직렬화).
  • 두 형식, 내 명령 그대로(§5): MP4 ≤1440p 병합, MP3 @ 64K.
  • React + TypeScript 단일 페이지 UI(영어) + 작은 TypeScript Node 서버.
  • 1인용(나만) — 비밀번호 하나(Basic Auth); 계정·가입·DB 없음.
  • VPS에서는 파일을 서버에서 생성 → 브라우저로 다운로드 스트리밍 → 자동 삭제.

범위 밖 (v1): 재생목록/일괄, 계정, DB, 재인코딩/자르기, 동시 작업.

2. 구조

브라우저 (React SPA) ──POST /api/download {url,format}──▶ Node 서버 (server.ts, 127.0.0.1)
   ▲                                                         │ spawn (인자 배열, 셸 없음)
   │  실시간 로그 (스트리밍)                                   ▼
   │                                                    download.sh ──▶ yt-dlp + ffmpeg
   │                                                         │            → ./downloads/<제목>.<확장자>
   └──GET /api/file/<id> (첨부)◀───────────────────────────────┘  전송 후 삭제 / TTL

  ── 개발: Vite(5173, HMR)가 /api 를 Node API(5174)로 프록시 ──
  ── 운영 / Phase B ──
인터넷 ──https──▶ CloudPanel nginx (TLS + Basic Auth) ──proxy_pass──▶ Node 서버 (127.0.0.1:5173, dist/ + /api)
  • 개발: Vite가 React 앱을 5173에서 핫리로드로 서빙하고 /api/*를 Node(5174)로 프록시.
  • 운영: Vite가 앱을 dist/로 빌드 → Node 서버가 dist/ 와 /api를 한 포트에서 서빙. 항상 127.0.0.1에 바인딩 — VPS에서도 nginx(CloudPanel)가 공개 면(TLS + 비번).
  • 브라우저는 유튜브와 직접 통신하지 않음 — 서버만(스크립트 경유).

5. 다운로드 스크립트 (download.sh) — 내 명령 그대로

서버는 bash download.sh "<URL>" "<mp3|mp4>" "<OUTDIR>"로 호출. 내 두 명령을 그대로 넣고, 앱이 파일 위치를 알 수 있도록 -o <템플릿>과 "$URL"만 추가:

#!/usr/bin/env bash
set -euo pipefail
URL="$1"; FORMAT="$2"; OUTDIR="$3"
TEMPLATE="$OUTDIR/%(title)s.%(ext)s"

if [ "$FORMAT" = "mp3" ]; then
  yt-dlp -f bestaudio --extract-audio --audio-format mp3 --audio-quality 64K \
         --no-mtime -o "$TEMPLATE" "$URL"
else
  yt-dlp -f "bestvideo[height<=1440][ext=mp4]+bestaudio[ext=m4a]/bestvideo[height<=1440]+bestaudio" \
         --merge-output-format mp4 --no-mtime -o "$TEMPLATE" "$URL"
fi

기존과 동일 — 정확히 내 MP4(≤1440p, 병합)와 MP3(bestaudio → mp3 @ 64K), --no-mtime 그대로.

6. UI (src/App.tsx) — React + TypeScript, 영어

라우터 없는 React 컴포넌트 하나. 상태(useState)가 URL, 선택한 Format, busy 플래그, 스트리밍 log, 결과 status를 담습니다. 제출 시 { url, format }를 POST하고, 스트리밍 응답 본문을 조각씩(getReader() + TextDecoder) 로그에 누적하며, 마지막 __FILE__ / __ERROR__ 표식 줄을 파싱해 결과를 보여주고 다운로드를 자동 시작합니다. 영어 UI: URL 입력("Paste a YouTube link"), MP3/MP4 라디오(기본 MP4), Download 버튼(작업 중 "Downloading…"), 실시간 <pre> 로그. (자세한 흐름은 HOW-IT-WORKS.md §3.)

7. 서버 (server/server.ts) 책임

  1. GET </api 아님> → serveFrontend: dist/의 빌드된 SPA 서빙(없는 경로는 index.html 폴백, 경로 탈출 방지). 개발에선 거의 안 거침(Vite가 UI 담당).
  2. POST /api/download { url, format }:
    • 검증: url은 호스트 youtube.com/youtu.be의 https://; format ∈ {mp3,mp4}. 아니면 400.
    • 직렬화: 이미 작업 중이면 429 (2GB RAM → 한 번에 1개).
    • spawn("bash", [SCRIPT, url, format, outdir]) — 인자 배열, 셸 문자열 아님(인젝션 방지).
    • stdout/stderr를 브라우저로 스트리밍(실시간 로그); 종료 0이면 __FILE__ <name> 표식으로 마무리.
  3. GET /api/file/<id> → Content-Disposition: attachment(UTF-8 파일명)로 파일 스트리밍, (VPS에선) 전송 후 삭제 / TTL.
  4. 항상 127.0.0.1 바인딩 (두 단계 모두).

8. Phase A — 로컬에서 만들고 테스트

  1. brew install yt-dlp ffmpeg node → 버전 확인.
  2. npm install (React, Vite, TypeScript, tsx). 확인: node_modules/ 생성, 에러 없음.
  3. chmod +x download.sh → 단독 테스트: mkdir -p downloads && ./download.sh "https://youtu.be/XXXX" mp3 "$PWD/downloads". 확인: .mp3 생성.
  4. npm run dev → http://127.0.0.1:5173 → URL → MP3 → Download. 확인: 파일 받아짐, 로그 실시간, 핫리로드 동작.
  5. MP4로 반복. 확인: 병합된 ≤1440p .mp4 재생.
  6. npm run build && npm start → http://127.0.0.1:5173. 확인: 빌드된 앱이 서빙되고 두 형식 모두 동작(VPS가 쓰는 운영 경로).
Phase A 완료 = 개발 과 운영 빌드 양쪽에서 두 형식 다운로드됨.

9. Phase B — IONOS VPS 배포 (CloudPanel)

서버 정보: IONOS VPS <VPS_IP>, Ubuntu 24.04, 2 vCore / 2GB RAM / 80GB NVMe, 앞단에 IONOS 방화벽 정책. (<VPS_IP> 등 배포 값은 .env에 보관 — gitignore됨; .env.example을 .env로 복사해 채우세요.)

  1. DNS: 서브도메인 A 레코드 → <VPS_IP>.
  2. IONOS 방화벽: 인바운드 80 + 443(및 SSH 22) 허용. CloudPanel 자체는 8443.
  3. 런타임 설치(root 아닌 sudo 사용자): 
    sudo apt update && sudo apt install -y ffmpeg
sudo curl -L https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp -o /usr/local/bin/yt-dlp
sudo chmod a+rx /usr/local/bin/yt-dlp
yt-dlp --version && ffmpeg -version
    (apt 말고 공식 yt-dlp 바이너리. 이후 sudo yt-dlp -U.)
  4. CloudPanel → Add Site → Node.js(또는 Reverse Proxy): 도메인 지정; nginx vhost + 앱 사용자 + 홈 디렉터리 생성.
  5. 코드 배포(git clone 또는 scp) 후 서버에서 npm install + npm run build(→ dist/ 생성). chmod +x download.sh, mkdir -p downloads.
  6. 서비스로 실행 — PM2: 
    sudo npm i -g pm2
pm2 start npm --name ytdown -- start    # npm start → tsx server/server.ts (127.0.0.1:5173)
pm2 save && pm2 startup                # 부팅 시 자동 시작
  7. 리버스 프록시: CloudPanel vhost에서 http://127.0.0.1:5173로 proxy_pass.
  8. TLS: CloudPanel → 사이트 → SSL/TLS → Let's Encrypt → 발급 + HTTPS 강제.
  9. 🔒 잠그기 (생략 금지): CloudPanel → 사이트 → Basic Auth → 사용자명 + 비밀번호. 1인용이라 그 비밀번호 하나가 전체 로그인 — 계정·DB 불필요. (선택: 내 IP만 허용 allowlist.)
  10. 스모크 테스트: URL 열기 → Basic Auth 입력 → MP3·MP4 다운로드. 확인: HTTPS로 동작; pm2 logs ytdown 깨끗.
Phase B 완료 = https://ytdown.yourdomain.com, 비밀번호 프롬프트, 두 형식 다운로드.

10. 보안 (공개 호스팅 — 타협 불가)

  • 앞단 인증: nginx Basic Auth 하나(9단계) — 1인용이라 그게 전체 로그인. 절대 열어두지 말 것.
  • 앱은 127.0.0.1 바인딩: 공개는 nginx만; Node 포트는 인터넷에서 닿지 않음.
  • 인젝션 방지: URL을 spawn 인자로; 셸 문자열 연결 금지; spawn 전 호스트 검증.
  • 레이트 리밋 + 직렬화: 한 번에 1개(§7); 선택적 nginx limit_req.
  • 비-root 사용자로 실행.
  • 디스크 위생: 정리 스윕 + 다운로드별 삭제로 80GB 안 채우기.

11. 운영 주의사항 (실제로 발목 잡는 것들)

  • ⚠️ 유튜브는 데이터센터 IP를 차단. VPS IP에서 yt-dlp는 같은 명령이 Mac에선 돼도 종종 "Sign in to confirm you're not a bot"으로 실패. 완화책: --cookies /경로/cookies.txt, 속도 조절, 간헐적 불안정 감안. VPS 버전은 로컬보다 불안정할 수 있음.
  • 2GB RAM: 직렬 1개엔 충분; 동시 작업 금지(§7).
  • 80GB 디스크: 자동 정리 중요.
  • yt-dlp 최신 유지: sudo yt-dlp -U(또는 주간 cron).
  • 업데이트/재시작: git pull && npm install && npm run build && pm2 restart ytdown.

12. 추후 추가 가능 (정말 필요할 때만)

  • UI에서 cookies 파일 업로드(봇 차단 회피용).
  • 재생목록 지원; 화질 선택(1080p/720p/1440p).
  • MP3에 썸네일 + 메타데이터 임베드(--embed-thumbnail --embed-metadata).
  • 간단한 작업 내역 / "최근 다운로드" 목록.
